Lot L17 de l'audit de couverture du 16/10/2026. Le CDC demande un « diagramme entités-relations à partir des §4.1–4.8, avec cardinalités ». Ce schéma est tiré des modèles (backend/app/models.py, 97 tables) : une relation est une clé étrangère ; une clé non nulle donne « exactement un » côté parent (||), une clé nulle « zéro ou un » (|o), une clé unique « au plus un » côté enfant (o|). Seules les entités du §4 du CDC et leurs liens figurent ici ; les tables d'exploitation (sessions, idempotence, travaux du poste, réglages, savoir-faire, itinéraires) n'y sont pas.

Régénérer la liste des clés (depuis backend/) :

uv run python -c "from app import models; from app.db import Base
for t in Base.metadata.sorted_tables:
    print(t.name, [(c.name, list(c.foreign_keys)[0].column.table.name, c.nullable, c.unique) for c in t.columns if c.foreign_keys])"

5. Les deux points d'attention du CDC

Point (§4.9) Choix du modèle Preuve
« Un acte peut servir plusieurs occurrences (et donc plusieurs fiches) sans produire autant de lignes de facturation » [T] occurrence.acte_id → acte_realise (plusieurs occurrences, un acte) ; cotation.acte_id unique : une cotation par acte, quel que soit le nombre d'occurrences servies backend/tests/test_medicaments.py::test_trois_frequences_qui_coincident_un_seul_acte_facturable ; au terminal SaisieFiche.occurrenceIds (MOD-47, 63B-6)
« Une fréquence peut servir plusieurs objets suivis ou un seul » [P] Un seul : frequence.objet_suivi_id (nul pour une fiche sans objet) ; deux objets du même soin ont chacun leur fréquence backend/tests/test_dispositifs.py::test_frequence_suit_l_objet_de_sa_fiche ; décision au registre : Q-97
